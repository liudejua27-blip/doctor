# ADR-0019：情境化行动建议与沟通摘要边界

| 属性 | 值 |
|---|---|
| ADR ID | ADR-0019 |
| 状态 | Proposed / 需产品、临床安全、隐私、数据、Agent 与 iOS 评审 |
| 日期 | 2026-08-09 |
| 决策范围 | 运动/工作情境、可选上下文读取、审核行动内容、面向不同接收者的摘要投影 |
| 关联功能 | FEAT-COMP-01、PRD-F11 |
| 关联规范 | PROD-01、UX-01、AGENT-01、DATA-01、SAFE-01、PRIV-01、API-01、QA-01 |

## 背景

产品的首要用户任务是处理一次运动、久坐办公或日常活动后出现的身体不适：用户先指出主观位置，再在 AI 的少量追问中补足情境、感觉、时间、影响与安全信息，随后获得安全的下一步，并可形成供自身、教练或专业人员沟通的摘要。

现有基础规范已具备用户确认、确定性安全、最小权限、`ActionPlan` 与不可变 `ReportSnapshot` 的边界，但需要明确以下跨域决策：

- “训练后”“久坐/工作后”应如何影响追问与内容选择，而不被误作病因或长期病史；
- AI 如何在用户允许时读取运动、工作与历史资料，而不形成默认全量记忆；
- 用户期待的动作、预防、饮食/补给建议如何避免成为未经审核的治疗或营养处方；
- 给医生与教练的产物如何有用而不被称为病例、病历或诊断报告。

## 决策

### 1. 会话情境是可撤回的本次交互意图，而不是单一病因标签

每个 `AssessmentSession` 可以在位置选择后持有一个用户可见的本次情境候选对象 `context_lens`。其 `selected_values` 是下列值的非空集合：`exercise_load`、`desk_work_load`、`daily_activity` 或 `unknown`。

- `unknown` 与其他值互斥；其余值可以并存。因此“运动和久坐都可能有关”必须保留两个已选情境，不能要求用户或模型选出单一原因；
- 多情境会话还必须有一个用户可见的 `analysis_subject`：指向本轮要补足的一个或一组已选 `marker_id + sensation`。它只决定普通问题的焦点，不能把其他位置、感觉或情境复制到该组；
- 若用户尚未选择 `analysis_subject`，Application Service 只能继续询问所有位置共用的基础事实，不能擅自把任一情境设为主因；
- 情境仅用于普通问题排序、覆盖范围判定、审核内容筛选与用户界面解释；它不是疾病、病因、受损组织、SafetyTier 或自动写入 `BodyProfile` 的长期事实；
- 若由 AI 从自然语言提出候选，必须以未确认候选显示；用户可修改、移除或改为“说不清”；
- 任何机器契约、数据库迁移或 API 新字段都须在本 ADR 获批后，先更新 DATA-01/API-01/Schema 与测试计划，再进入实现。

### 2. 资料读取须由 Application Service 独占的“本次实际使用资料”收据约束

AI 默认只使用当前会话已输入的结构化内容。读取运动习惯、工作情境、同部位历史、设备或上传资料时，必须逐来源校验同意、用途、时间范围、字段白名单、所有权和新鲜度。

`DataUseReceipt` 不是 Agent 可变对象。每个来源必须由 Application Service 追加一条最小、脱敏的状态记录：`requested`、`user_declined`、`policy_denied`、`no_data`、`stale`、`read`、`included_in_model_context`、`tool_failed` 或 `not_used`。其中“已授权”“已读取”“实际进入模型上下文”是三个不同事实，均不得由模型自行声明。

最终安全响应/行动页面必须显示或可打开本次实际使用资料收据：类别、来源、时间范围、用途、状态、同意/字段白名单版本与显示/保留引用。撤回同意、变更来源 revision、过期或工具失败会使后续普通分析和任何行动预览失效。拒绝可选资料读取后，核心手动记录、事实复核和安全路径仍可完成。

### 3. 问题选择由确定性 `QuestionPlan` 先行，行动计划只从审核内容库产生

在调用 PydanticAI 前，Application Service 必须使用版本化、可测试的 `QuestionPolicy` 生成至多一个普通 `QuestionPlan`。它只可引用审核普通问题目录中的问题 ID、目标事实组、答案类型/选项、“不确定”语义、提问理由、适用情境/覆盖范围和版本。

安全必答项由 SafetyGate 和审核安全目录的 `required_question_ids` 独占，必须在普通路径前完成；它们不属于普通 QuestionPolicy 或普通 QuestionPlan。只有安全结果为 `complete + supported + R3 + unresolved_safety=false` 时，普通 QuestionPolicy 才可按“缺失共用基础事实 → 当前 `analysis_subject` 的已选情境事实”选择一题。可选资料和审核行动匹配的补充事实不属于首个 P1I 切片，必须在另行批准的 Feature/ADR、资料收据、内容审核和契约完成后才可加入。已确认且仍新鲜的事实不得重复问；冲突、过期或用户明确修订时必须以可解释原因重新询问。PydanticAI 只能从当前计划的回答中提取未确认候选并在允许范围内生成自然语言，不能自由决定安全题、问题目录、问题顺序、行动或结束条件。

### 4. 行动计划只从审核内容库产生

`ActionPlan` 继续只由 Application Service 组合有效 `ApprovedGuidance`：每项须绑定 SafetyTier、已确认事实、适用人群/场景、内容版本、排除条件、停止/升级条件和理由。

- R0/R1 不显示普通行动；R2 不用自我管理替代专业评估；
- R3 只允许经审核的观察、负荷/工作情境调整、可选低风险舒适活动、复查与一般恢复支持；
- 模型不能自由生成动作、拉伸、食物、补剂、药物、剂量、治疗方案、恢复承诺或复出许可；
- 首发不开放针对不适的具体食物、补剂或剂量建议。未来的营养能力须另立 Feature Spec、临床/营养审核、地区内容、隐私与测试门禁；
- 若没有完整匹配内容，关闭该行动类别并进入更保守路径，不能由模型补写。

在最终保存前，用户可见的只能是 `ActionPlanPreview`：它由首次事实复核后的 `DecisionFactSnapshot`、当前 SafetyBaseline、内容 release 和资料收据摘要共同绑定。用户修改任一事实、位置/感觉关联、情境、授权资料、规则或内容版本时，预览必须立即失效并重新计算；它不是正式 Event 的行动快照，也不能独立复用。只有第二次明确批准和权威读回成功后，才可冻结为 Event/Report 使用的 `ActionPlan`。

### 5. 沟通摘要是同一报告的受控显示投影

不新建“病例/病历”领域对象。现有不可变 `ReportSnapshot` 按用户主动选择的接收者与字段范围，提供以下显示类型：

- `self_body_signal_report`：身体信号报告；
- `clinical_communication_summary`：就诊沟通摘要；
- `training_communication_summary`：训练沟通摘要。

它们均不是诊断报告、法定病历、医疗证明、EMR 写入或已被医生/教练审核的结论。接收者类型影响默认最小字段范围，不替代用户在分享前的逐次确认。

## 后果

### 正面

- 产品主体验围绕真实用户任务，而非孤立地图、档案或开放式聊天；
- 运动/工作语境使高价值追问与审核内容更可解释；
- 用户可看见 AI 用了什么资料，并保持“仅使用本次记录”的控制权；
- 行动、复查与沟通摘要有清晰的安全、确认与内容版本边界；
- 现有 PydanticAI、RealityKit、2D 回退和双阶段确认架构无需被推翻。

### 成本与风险

- 需跨端定义可多选的 `context_lens`、`analysis_subject`、资料使用收据、问题计划、行动预览/引用与报告显示类型的兼容契约；
- 需建立运动/工作情境的审核内容、可用性研究和安全锁定集；
- 具体运动、舒适活动、营养与地区内容会增加临床、营养、法务和本地化审核成本；
- 若把“可能相关情境”或 3D 精确位置表述成病因/组织结论，会触发安全与合规风险。

## 被否决的替代方案

### A. 开放式“AI 医生”聊天

否决。它使病名、药物、动作、饮食和疾病概率容易越过审核内容与安全门，且无法保证资料来源、确认与保存边界。

### B. 只做身体地图、强度与档案

否决。它无法完成用户“这次应该怎么办”的核心决策任务，会把结构化记录误做成被动日志。

### C. 将情境自动写入长期档案或默认读取所有历史

否决。单次训练/办公情境不应成为默认永久事实；默认读取会违反最小必要与用户可见控制。

### D. 将输出称为病例或病历

否决。产品不产生法定医疗记录，且“病例/病历”会制造医生审核、诊断或 EMR 集成的错误预期。

## 退出条件与后续工作

在本 ADR 获批准且进入实现前，必须完成：

1. 将 FEAT-COMP-01 的稳定需求映射到 PROD-01、UX-01、AGENT-01、DATA-01、SAFE-01、PRIV-01、QA-01、TRACE-01；
2. 由临床安全与营养审核锁定行动内容分类、支持场景、停止条件与禁止内容；
3. 将新的上下文/分析焦点/问题计划/收据/行动预览/报告显示类型更新到 API/JSON Schema，并提供兼容策略与契约测试；
4. 为运动与久坐办公两类用户建立安全、隐私、可用性和真实设备验证证据；
5. 未满足上述条件前，保持具体动作、营养/补给和真实 Provider 上下文读取能力关闭。
6. 在正式替代旧 ADR 的 R2/R3 普通 Agent 表述前，按 [CONFLICT-001](CONFLICT-001-r2-ordinary-agent-gate.md) 的更保守临时行为执行：普通 Agent 仅限完整、支持、无未解决安全的 R3；R2 只使用固定专业评估准备。
7. 在 P1I 实现前，按 [CONFLICT-002](CONFLICT-002-question-selection-authority.md) 的保守临时行为执行：SafetyGate 独占安全题，Application Service 独占普通问题选择；P1I-OPEN-001～006、DATA/API/Schema 和锁定测试未完成时不实现或启用普通 QuestionPlan。
