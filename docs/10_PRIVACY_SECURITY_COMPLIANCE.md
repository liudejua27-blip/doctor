## 1. 目的与原则

AI Body Companion 处理主观身体信号、活动背景、历史事件、可选 HealthKit 数据和用户上传资料。这些数据可以直接或间接反映医疗健康状况，必须按敏感个人信息进行高保护设计。

本文档定义：

- 收集、使用、存储、共享、删除数据的目的和边界；
- 分层、分场景和可撤回的同意体系；
- Agent 最小权限和逐来源授权；
- 第三方模型、HealthKit、上传文件和跨境处理要求；
- 加密、访问控制、日志、审计和事件响应；
- 用户查阅、复制、纠正、撤回、导出和删除权；
- Apple 平台、中国大陆个人信息与生成式 AI 合规门禁；
- 与 `SafetyBaseline` 绑定的隐私版本和可重建证据。

核心原则：

1. **目的限定**：每类数据只有明确、公开、经批准的用途。
2. **最小必要**：完成当前任务需要什么，就只读取什么。
3. **逐来源授权**：Agent “聪明”不等于默认读取用户全部资料。
4. **事实可追溯**：用户自报、设备数据、文档、专业人员信息和 AI 推断必须分开。
5. **默认保护**：模型训练、营销、跨境、报告分享和长期记忆默认关闭或单独授权。
6. **用户控制**：用户能看到本次分析使用了哪些资料，并能纠正、撤回和删除。
7. **安全不降级**：隐私或依赖故障时进入 `DegradedMode`，不得绕过权限换取正常体验。
8. **证据优先**：隐私政策、App Store Privacy、系统权限用途、SDK 实际行为和服务端数据流必须一致。

P2A 的 Session/Turn 投影不改变这些边界：owner 只保存在服务端索引，稳定结果不含 user ID、原始输入、内部 Prompt、访问令牌或正式资源引用；candidate 仍是未确认数据。P2A ledger 只用于合成数据的进程内验证，重启丢失且默认关闭，不能作为真实健康资料存储、删除完成或跨实例访问审计证据。

P2B 进一步把敏感输入拆成“服务端受控依赖”和“客户端可见元数据”：`SafetyEvaluation`、`UserTurnInput`、候选 `AssessmentDraft`、EpisodeSelection 和 Agent 版本只可由已绑定的服务端 application caller 传入/保留；`ConfirmationIntentApplicationResult` 不得包含 raw text、Safety answers、候选事实、user ID、Provider key 或正式 Event/Episode/Report 引用。P2B 的内存 ApprovalIntent 与幂等 ledger 只用于合成数据验证，默认关闭且重启丢失；它不能证明真实用户已同意、已完成重新认证、已写入档案或已执行删除。若服务失败、权限失效或结果丢失，iOS 必须保留本地未确认草稿并回到安全入口，不得显示“已保存”。

P2C 继续沿用同一最小披露边界：`P2CApprovalDecisionApplicationService` 只接收服务端绑定的 P2B metadata、当前 pre-approval revision 和 typed approve/deny；它把 candidate/raw/Safety/Agent 版本留在隔离 prototype store，结果只返回 terminal Approval metadata、必要的 event ref 和 prospective lifecycle。所有权、终态重放、过期和 key 冲突在服务端先判断；P2C 内存 map 重启丢失，不证明跨设备授权、近期重新认证、Consent、审计、删除传播或正式 Event 保存。P2C 结果和错误日志不得包含健康正文；详情见 [FEAT-P2C](18_IMPLEMENTED_PROTOTYPE_BASELINE.md)。

P2D 进一步把 repository 事务回执限制为 metadata-only：只保留 transaction/session/approval 脱敏 ID、digest、revision、有限 write-set、状态、结果引用和原子性/重放标记；receipt、异常和审计日志不得包含 owner 身份、candidate、raw text、Safety answers、Prompt、Provider 响应或 Event/Episode 正文。P2D prototype/fake repository 默认关闭、重启丢失，不证明真实数据库加密、审计、Consent、删除传播或跨实例恢复；commit/read-back 超时必须回到 P4 未确认草稿，不显示已保存。详情见 [FEAT-P2D](18_IMPLEMENTED_PROTOTYPE_BASELINE.md)。

P1-A `BodyAssetManifest` 是非用户、非健康事实的资产供应链 metadata，但其 `asset_id/version/topology_id` 会间接出现在 `BodyLocation` 的位置引用中，故必须纳入版本、权限和撤回审计。清单不得携带用户 ID、原话、身体点击坐标、感觉、强度或 Agent 输出；普通日志只记录清单版本/失败类别和不可逆关联 ID。`BodyAssetRuntimeGate` 未通过时保留 2D/列表，不通过下载未签名模型来“补救”；真实资产的许可证、签名密钥、文件哈希、作者链和 App Store 权利另走 OSS-01/ADR-0018 的供应链门。

本文档是产品与工程规格，不替代首发地区律师、隐私官、监管顾问或 Apple 审核意见。

## 2. 法律与平台基线

以下官方页面与平台规则于 2026-08-05 核验；本节只形成设计门禁，不代替对实际主体、数据流、模型供应商和发布地区的法律意见。

### 2.1 中国大陆

公开发布前必须根据实际主体、用户规模、供应商和部署地区完成法律适用性判断，至少覆盖：

- 《中华人民共和国个人信息保护法》：医疗健康信息属于敏感个人信息；处理敏感个人信息需要特定目的、充分必要、严格保护，并在适用时取得单独同意；处理敏感信息、自动化决策、对外提供和跨境等高风险活动需要事前影响评估。
  https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html
- 《中华人民共和国数据安全法》和《中华人民共和国网络安全法》。
- 《生成式人工智能服务管理暂行办法》：输入信息、使用记录、个人信息、投诉举报和服务安全义务。
  https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm
- 生成式人工智能服务备案/登记与模型信息公示要求。
  https://www.cac.gov.cn/2024-04/02/c_1713729983803145.htm
- 《人工智能生成合成内容标识办法》及配套标准：AI 生成文本、图片、音视频和导出内容的显式/隐式标识。
  https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm
- 若未来形成持续性人格模拟和情感互动，还需要重新评估《人工智能拟人化互动服务管理暂行办法》。首发维持功能型身体信号助手，不以情感依赖为目标。
  https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm
- 国家卫健委互联网诊疗规则所体现的 AI 不替代医师、不自动生成处方边界。
  https://www.nhc.gov.cn/yzygj/c100068/202203/2072f0e8988249e59d942e1b2a933916.shtml

### 2.2 Apple

必须持续核对：

- App Review Guidelines 1.4、5.1、健康数据与账户删除要求；健康/医疗数据不得用于广告、营销或不允许的数据挖掘，个人健康信息不得存入 iCloud。
  https://developer.apple.com/app-store/review/guidelines/
- HealthKit 隐私与逐数据类型授权；权限应在用户触发相关功能时申请，并提供清楚用途说明。
  https://developer.apple.com/documentation/healthkit/protecting-user-privacy
- App Store Privacy Nutrition Label 与第三方 SDK 数据实践。

### 2.3 合规变化

法律、平台政策、供应商条款或数据部署发生变化时，必须：

1. 创建变更记录；
2. 更新数据流图和风险评估；
3. 判断是否需要重新同意；
4. 更新 Privacy Release Manifest，并提升 `consentNoticeVersion`；
5. 形成新的 `SafetyBaseline`；
6. 通过本文与测试文档定义的发布门禁。

运行时模型不得自行解释法规并改变产品行为。

## 3. 用户范围与特殊人群

- MVP 仅面向 18 岁及以上用户。
- 18 岁边界是当前产品范围草案，不是已确认的医学阈值；公开发布前必须由临床安全、隐私法务和产品共同批准。
- 年龄范围确认必须在首次记录和账户创建前完成。
- 若无法确认用户已满 18 岁，不得进入云端 Agent 和长期健康档案流程；可以展示不处理健康信息的公开说明和紧急帮助入口。
- 不得通过收集完整身份证号码来实现普通年龄确认，除非有独立、必要、合法的业务依据和影响评估。
- 未来开放未成年人前，必须单独设计监护人同意、未成年人模式、专门隐私规则、数据最小化、内容审核和退出机制，并生成新的 Safety Case。
- 妊娠、术后、肿瘤、免疫抑制等不是身份识别标签的默认收集项。仅当用户主动提供或已审核场景确有必要时收集，并说明用途。

## 4. 数据分类与处理目的

### 4.1 数据类别

| 数据类别 | 示例 | 敏感级别 | 默认处理 |
|---|---|---|---|
| 账户与安全 | 随机用户 ID、登录凭证、设备会话、风控信号 | 高 | 与健康内容分离；凭证进 Keychain/服务端安全存储 |
| 基础资料 | 年龄段、活动类型、职业姿势、惯用侧 | 高 | 可选字段最小化；逐项显示来源和更新时间 |
| 身体信号事件 | 原话、位置、侧别、感觉、程度、时间、功能影响 | 极高 | 加密、最小权限、用户确认后写入 |
| 安全评估 | 安全问题答案、命中规则、R0–R3、用户操作 | 极高 | 独立审计；不进入普通分析日志 |
| Agent 推断 | 候选结构、可能相关因素、摘要、未确认项 | 极高 | 与事实分层；未确认不得长期生效 |
| 2D/3D 标记 | 身体区域、局部坐标、模型版本 | 极高 | 视为健康信息，不作行为广告 |
| HealthKit | 活动、训练、睡眠等经授权数据或摘要 | 极高 | 首发不依赖；后续逐类型只读授权 |
| 上传资料 | PDF、图片、报告、文字、OCR、提取字段 | 极高 | 隔离处理；原文和提取字段分别管理 |
| 语音与图片原始文件 | 录音、照片、扫描件 | 极高 | 短期处理；具体保留期限必须在发布前批准 |
| 报告与分享 | 报告快照、分享链接、接收者和撤回状态 | 极高 | 用户主动触发；默认私有、可过期和撤回 |
| 通知 | 复查提醒、通知偏好、送达状态 | 高 | 锁屏默认中性，不含身体部位和程度 |
| 产品分析 | 页面、性能、崩溃、非健康事件 | 中 | 与健康内容隔离；禁止原始文本和位置 |
| 安全审计 | 版本、权限、访问、规则、输出哈希、回滚 | 高 | 防篡改、最小化、独立保留策略 |

### 4.2 目的登记

每个数据字段必须登记：

- `data_field_id`；
- 数据类别与敏感级别；
- 明确处理目的；
- 是否为核心服务必要；
- 收集来源；
- 使用者与处理者；
- 存储位置和地区；
- 允许的 Agent 工具；
- 是否会发送第三方；
- 是否涉及跨境；
- 保留规则；
- 删除路径；
- 同意或其他合法处理基础；
- 隐私告知版本；
- 对应测试 ID。

未登记字段不得进入生产采集、日志、模型上下文或分析仓库。

## 5. 同意与权限体系

### 5.1 同意必须分层

以下事项不得合并成一个“同意所有”开关：

| 同意/权限 | 是否核心 | 默认 | 必须说明 |
|---|---:|---:|---|
| 核心身体信号记录与账户存储 | 是 | 用户主动同意 | 数据类别、目的、保留、权利和删除 |
| 云端 AI 结构化与摘要 | 否；应提供降级记录路径 | 关闭 | 哪些字段发送、处理目的、AI 局限 |
| 第三方模型处理 | 否 | 关闭 | 供应商/接收方、数据类别、地区、保留、是否训练 |
| 读取既往身体事件 | 否 | 关闭 | 查询范围、用途、如何撤回 |
| Agent 长期记忆 | 否 | 关闭 | 哪些信息会长期保存、来源和更新方式 |
| HealthKit 每类数据 | 否 | 系统默认未授权 | 数据类型、为何需要、拒绝后的手动路径 |
| 上传 PDF/图片/文字 | 否 | 每次主动选择 | 文件处理、OCR、原文保留和注入风险 |
| 原始语音处理 | 否 | 每次或明确范围授权 | 是否端侧、是否上传、删除时点 |
| 报告分享 | 否 | 每次主动确认 | 接收方、字段、有效期、撤回能力和外部副本限制 |
| 通知 | 否 | 关闭 | 通知类型与锁屏隐私 |
| 产品改进分析 | 否 | 关闭或仅无健康内容分析 | 不影响核心功能 |
| 使用敏感交互数据训练模型 | 否 | 关闭 | 必须单独、明确、可撤回；不得捆绑 |
| 跨境提供个人信息 | 否 | 关闭 | 境外接收方、目的、方式、种类、权利路径 |

“不同意可选处理”不得导致核心结构记录无法使用。若云端 AI 未授权，但确定性安全规则、核心记录同意和服务端验证可用，产品进入 `ManualMode`：允许手动填写、同步 typed draft，并通过两阶段确认生成不含 AIInterpretation 的正式 Event；离线时先保留本地草稿。只有规则/验证不可用时才进入只能保存未确认草稿的 `DegradedMode`，不得借故强迫 AI 同意。

### 5.2 同意收据

每次同意或撤回应生成不可变 `ConsentReceipt`：

- `consent_receipt_id`；
- 用户伪名 ID；
- 同意范围 ID；
- 告知文本与版本；
- 数据类别和目的；
- 处理者、受托人或接收方；
- 地区与跨境状态；
- 用户动作、时间和客户端版本；
- 生效与撤回时间；
- 适用 `SafetyBaseline`；
- 替代路径是否提供；
- 证明文案已展示的 UI 版本。

不得只保存一个布尔值。处理目的、方式、数据种类、接收方或跨境状态发生实质变化时，必须判断是否重新取得同意。

### 5.3 撤回

- 用户必须能在 App 内便捷撤回每个可选范围。
- 撤回后，新的 Agent 请求不得继续读取该来源。
- 已生成上下文缓存、搜索索引和派生数据必须按删除/失效规则处理。
- HealthKit 权限由系统设置管理；App 中应提供状态说明和跳转，不复制或伪造系统权限页。
- 撤回不应删除用户未要求删除的确认事件，但必须停止相关新处理。
- 若某项处理属于法律要求或安全审计必要保留，必须在告知和保留计划中明确，并隔离限制用途。

### 5.4 自动化处理透明度、纠正与申诉

- 界面必须明确区分：确定性规则产生 SafetyTier，LLM 只产生候选提取与受限解释，专业人员并未实时审核本次结果。
- 用户必须能查看本次使用的数据类别、确认事实、命中规则的用户可理解说明、内容来源和 `safetyBaselineId`。
- 用户可以纠正事实、拒绝 AI 草稿、改用手动记录，并在修改安全相关事实后触发规则重算。
- 产品不得把身体信号或 SafetyTier 用于广告定向、就业、保险承保/定价、信用、差异化收费或其他对个人权益有重大影响的自动化决定。
- 若未来把自动化结果用于对个人权益有重大影响的决定，必须在启用前另行完成法律评估、解释与人工复核/拒绝机制，并建立新的 ADR 和 SafetyBaseline。
- 隐私或数据权利申诉必须有可追踪的人工处理渠道；该渠道不得宣传为即时医疗复诊或让用户因此延误紧急帮助。

## 6. Agent 最小权限与上下文控制

### 6.1 工具级授权

Agent 不直接访问数据库。它只能获得当前状态显式注册的最小只读或候选提议工具。下表同时列出应用服务边界，是为了明确哪些能力绝不能注册给 Agent：

| 能力/工具 | 调用者 | 默认权限 | 强制限制 |
|---|---|---|---|
| `read_current_draft` | Agent 经受控服务 | 当前 Episode | 只读当前用户、当前草稿 |
| `read_profile` | Agent 经受控服务 | 未授权不可读 | 只返回当前任务所需字段、来源、revision 和更新时间；P3 使用 `AgentReadContext` |
| `read_confirmed_events` | Agent 经受控服务 | 未授权不可读 | 限定身体区域、Episode、时间范围和结果数量；P3 只返回已确认摘要 |
| `read_historical_events` | Agent 经受控服务 | 必须单独的 `historical_events_read` scope | 只返回当前用户已确认历史摘要；不得由 `current_episode_read` 或缓存隐式扩大 |
| `read_activity_sleep_summary` | Agent 经受控服务 | 未授权不可读 | 只读已授权类型和摘要；不得获取无关原始样本 |
| `read_uploaded_source` | Agent 经受控服务 | 每次显式授权 | 返回必要片段、页码、来源和置信度 |
| `run_safety_rules` | Application Service | 必须可用 | 先于普通 LLM；Agent 只能提交候选线索请求复核，不能决定是否运行、修改规则或 Tier |
| `save_confirmed_event` | Application Service | 永不注册给 Agent | 用户确认后重新认证、授权、校验版本并事务写入 |
| `create_share` | Application Service | 永不注册给 Agent | 需要本次分享确认、字段清单、有效期与事务审计 |

每次工具调用必须验证：

- 当前用户和会话；
- 同意范围；
- 数据用途；
- 最小字段；
- 时间和身体区域范围；
- SafetyBaseline 兼容性；
- 调用频率与异常模式；
- 审计事件。

### 6.2 上下文包

发送给模型的 `AgentContextPackage` 必须：

- 使用伪名会话 ID，不包含不必要的直接标识符；
- 只包含当前任务所需数据；
- 给每个事实标注来源、时间、确认状态和新鲜度；
- 明确区分用户原话、设备数据、文档提取与 AI 推断；
- 不包含已撤回、已删除、过期或不相关资料；
- 不包含第三方联系信息，除非用户正在执行明确分享或联系动作；
- 在模型请求前经过字段白名单和敏感数据检查；
- 记录上下文包哈希和字段类别，不在普通日志保存完整正文。

### 6.2.1 本次实际使用资料收据（ADR-0019 Proposed）

用户在完成或查看一次 AI 身体助手会话时，必须能查看本次实际使用资料收据。它是最小透明度与审计投影，不是新的长期健康档案，也不保留原始对话：

| 字段 | 要求 |
|---|---|
| 资料类别 | 当前会话、活动/工作背景、同部位历史、设备摘要、上传资料等；不得用“全部资料”笼统表示 |
| 脱敏来源引用 | 只含可审计的来源 ID/revision 或类别，不展示不必要的健康正文 |
| 时间范围 | 本次读取或摘要覆盖的时间范围；无数据、过期、拒绝与未读取必须可区分 |
| 用途 | 例如追问排序、趋势比较或审核内容筛选；不得写成诊断或训练用途扩张 |
| 实际使用结果 | 已使用、用户拒绝、无数据、过期、策略拒绝或未使用；不能把已授权等同于已读取 |
| 授权与版本引用 | 同意收据、字段白名单、SafetyBaseline/内容或工具版本的最小引用 |
| 展示与保留 | 展示时间、摘要哈希和脱敏审计；普通日志、崩溃与产品分析不得保存原始健康内容 |

默认只使用当前会话的最小结构化事实。读取运动习惯、工作情境、历史 Episode、HealthKit、上传资料或长期记忆必须分别满足同意、用途、范围、所有权、新鲜度与字段白名单校验。用户拒绝任何可选来源后，仍可完成核心手动记录、事实复核与安全路径。

### 6.3 长期记忆

- 默认不启用黑盒式长期对话记忆。
- 可长期使用的信息必须成为用户可见、可编辑、有来源和更新时间的档案字段。
- 旧资料与当前说法冲突时，Agent 只能请求确认，不能静默覆盖。
- 文档中出现的疾病名称只能表述为“某份、某日、某来源的资料曾记录”，不能自动变成当前事实。
- 用户删除长期记忆后，必须清除主库、索引、缓存和可恢复副本中的可识别内容。

## 7. HealthKit 与 Apple 数据

### 7.1 首发原则

- MVP 不依赖 HealthKit。
- 拒绝 HealthKit 后仍必须能手动完成身体记录。
- 首发不启用 Clinical Health Records。
- 不向 HealthKit 写入 AI 推断、SafetyTier、可能病因或非用户确认内容。
- 个人健康信息不得存入 iCloud、CloudKit 或 iCloud 文档容器。

### 7.2 后续接入要求

每个 HealthKit 数据类型必须有独立评审：

- 与具体产品功能直接相关；
- 在用户触发该功能时申请；
- 使用 Apple 系统权限界面；
- 配置准确、完整的用途说明；
- 读取权限与写入权限分离；
- 只请求最小时间范围和必要类型；
- 明确派生摘要算法；
- 处理用户撤回、删除或在 Health App 中修改数据；
- 不能因无数据判断用户明确拒绝了读取权限；
- 不用于广告、营销、保险画像、价格差异或数据经纪；
- 不与第三方 AI 共享，除非另有明确、合法的同意和供应商评估。

### 7.3 App Store 一致性

发布前必须逐项对齐：

- Info.plist 权限用途；
- App 内权限前置说明；
- 隐私政策；
- App Store Privacy；
- App Review Notes；
- SDK 网络流量；
- 实际数据库和日志；
- 第三方模型请求；
- 账户删除与数据删除能力。

任何一项不一致都属于发布阻断。

## 8. 第三方模型、供应商与跨境

### 8.1 供应商准入

模型、OCR、语音、对象存储、分析、崩溃和通知供应商必须建立登记：

- 法律实体、服务和子处理者；
- 数据类别和处理目的；
- 处理、存储和备份地区；
- 保留与删除承诺；
- 是否将输入/输出用于训练；
- 加密与访问控制；
- 安全认证和事故通知时限；
- 政府/执法请求流程；
- 数据导出和服务终止后的删除；
- 合同、数据处理协议和审计权；
- 中国大陆备案/登记与服务可用性；
- 供应商变更和替代方案。

供应商默认不得使用用户健康数据训练其通用模型。仅关闭 UI 开关不够，必须通过合同、API 配置和验证证据共同证明。

### 8.2 跨境

中国用户数据不得默认发送境外模型服务。实施跨境前必须：

1. 证明业务必要性和最小范围；
2. 完成个人信息保护影响评估；
3. 确认适用的出境机制；
4. 告知境外接收方、联系方式、目的、方式、种类和用户权利路径；
5. 在适用时取得单独同意；
6. 完成供应商与子处理者审查；
7. 建立撤回、删除、访问和事故响应路径；
8. 更新数据流、隐私政策和 SafetyBaseline；
9. 通过跨境阻断与区域路由测试。

如果无法完成上述要求，必须使用境内部署或不发送该类数据。

### 8.3 模型备案、信息公示与 AI 标识

面向中国大陆公众提供生成式 AI 功能时，发布前必须完成：

- 所用模型备案/登记适用性判断；
- 产品显著位置公示模型名称和备案/登记信息的适用要求；
- 交互界面明确提示用户正在与 AI 而非自然人互动；
- 对生成、导出、分享的文本、图片、音视频和虚拟场景执行适用的显式与隐式标识；
- 用户协议说明标识方式；
- 投诉举报入口和处理流程；
- 禁止用户或系统恶意移除依法必须保留的标识。

“AI Body Companion”首发必须维持功能型助手定位；若产品转为持续情感互动，必须重新做拟人化互动服务适用性和安全能力评估。

## 9. 上传资料与语音

### 9.1 上传资料

上传文件必须经过隔离处理：

- 类型、大小、恶意文件和内容扫描；
- 与生产应用进程和 Agent 工具隔离解析；
- 不执行宏、脚本、嵌入对象或外部链接；
- 将文档中的 Prompt、系统指令和工具调用文本视为不可信内容；
- OCR/提取结果保留页码、区域、来源和置信度；
- 低置信度字段不得成为确认事实；
- 用户逐项确认后才能进入档案；
- 原始文件与提取字段具有独立保留和删除状态；
- 删除原始文件时同步处理预览、缩略图、OCR 中间件、索引和缓存。

### 9.2 语音

- 优先端侧转写或端侧预处理。
- 如需上传，必须在使用前说明供应商、数据类别和删除规则。
- 原始录音不得进入普通分析、崩溃日志或模型训练。
- 原始录音的最大保留时长必须在发布前写入正式保留计划；该值未批准前不得上线云端录音。
- 用户确认文本后，应按声明的最短周期删除原始音频，除非用户为明确目的另行选择保留。

## 10. 存储与加密

### 10.1 iOS

- 登录令牌和设备密钥使用 Keychain，并配置与威胁模型一致的可访问级别。
- 本地健康草稿使用 iOS Data Protection，设备锁定时不可访问。
- 本地数据库、缓存、缩略图和导出文件按敏感数据保护。
- 不把健康正文写入 UserDefaults、剪贴板历史、Spotlight、通用日志或崩溃报告。
- 共享前生成临时文件，使用后安全清理；分享页面明确接收方和内容。
- App 切换到后台时，任务切换器快照隐藏身体信号详情。
- 通知默认使用中性文案，不在锁屏显示部位、感觉、程度、SafetyTier 或报告摘要。
- 支持 Face ID/Touch ID 作为可选的 App 内再次验证，但不得误称其替代账户安全。

P4 的 `InMemoryEncryptedDraftStore` 只是在 Swift Core 中验证 AES-GCM、账户派生密钥、认证失败和幂等删除；它不是上述生产要求的替代物。P4 `schema_version=1.1` 的加密 payload 还必须保留感觉—位置关系，位置 ID 唯一且关系不悬空；旧 `1.0` code-only 草稿不可被恢复逻辑猜测或扩展。生产实现必须补齐 Keychain 可访问级别、Data Protection、设备锁定/备份迁移、密钥轮换、文件原子写、后台快照和真机恢复证据后，才可将 `NFR-REL-001` 标为通过。同步队列的 `accepted_unconfirmed` 不得进入正式 Event、报告或审计正文；删除/过期必须清理本地密文、队列正文和可恢复密钥，并留下不含健康正文的回执。

P1D 的 `SignalIntakeDraft` 只允许在受保护的未确认草稿边界中保存结构化字段和可选原话：来源/状态、位置、感觉、程度、时间、因素和功能影响用于本轮复核，不默认写入 Profile 或长期记忆。普通日志、崩溃和遥测只可记录 phase、错误类别、draft revision 与脱敏 ID；不得记录 `rawUserText`、完整位置、感觉或程度。P1E 适配结果继续剥离原话、身份和正式资源引用，不把客户端 `profile` 枚举当作授权读取。Profile/HealthKit/上传资料在未来接入时必须使用 P3 的 typed、scope/owner/expiry/allowlist 投影，并由服务端重新检查同意；P1D/P1E 当前实现不读取这些来源。

P1-C `P1CResearchRecorder` 是独立的、默认关闭的进程内研究元数据边界，只能保存受限参与者别名、固定任务/入口/版本/flag、时间、固定错误/停止规则、三项理解结果、回退和澄清次数。它不接收或派生身体位置、感觉、强度、时间内容、功能影响、原话、账号 ID、模型内容、录音或录屏，不写 UserDefaults、健康档案、普通遥测、PydanticAI 上下文或 P4 队列；删除只清空内存且可重复执行。Schema 与 [ADR-0017](decisions/ADR-0017-p1c-ux-research-instrumentation-boundary.md) 是其边界真源。任何真实招募、录音/录屏、上传、研究仓或跨境处理都必须另行完成 REL-01 GATE-08 的同意、伦理、保留和删除审核。

P1F 只允许 Application Service 将 `raw_user_text` 作为 SafetyEngine 的短生命周期输入；它不得进入 handoff JSON、固定错误码、普通日志、遥测或 Agent-ready 结果。P1F 的 `server_safety` 是去除答案原文的规则投影，`AssessmentDraft` 仍是未确认候选；任何 Provider 发送自由文本、长期保存或公开 API 映射都必须另行完成隐私/同意评审。

P1G 只接收 P1F 已脱敏的 `AssessmentDraft`，由固定 prompt builder 生成数据区；它不接收 P1D `raw_user_text`、安全答案原文、用户身份、token、Provider key 或完整 PydanticAI message history。P1G 工具读取必须通过 P3 `AgentReadContext` 的 scope/owner/expiry/allowlist，并仅留下 source ID、scope、版本和结果类别。普通日志、崩溃和遥测不得记录 prompt、模型响应、工具正文或隐藏推理；真实 Provider、结构化短文本的跨境/留存和 Consent 仍是未决项。

P1H 的 transient ledger 只保存进程内主体绑定、Turn 元数据、canonical request digest 和脱敏 `AgentTurnApplicationResult`；不得保存原始 prompt、PydanticAI messages、用户原话、工具 projection、Safety answers 或完整请求序列化。相同 key 的重放只返回同一已接受 result；来源清理或进程重启后不得恢复旧健康正文。P1H 不接收自由回答、不绕过 P1F 安全，不创建 Approval/Event/Episode/Report；真实多轮持久化、删除 TTL、跨设备 CAS 和 Provider 留存仍需单独隐私评审。

#### 10.1.1 内部 P0 App Host

[FEAT-IOS-P0-RUNTIME-01](28_IOS_P0_RUNTIME_HOST.md) 的 `BodyCompanionInternal` 仅是 Simulator 工程 Host，不是可处理生产健康数据的客户端。它必须以固定内部能力集运行：不发起网络/Provider/API 请求，不请求 HealthKit、通知、相机、麦克风、照片、位置或其他系统权限，不使用 Keychain、UserDefaults、文件、数据库、iCloud 或共享容器保存健康草稿，且不引入产品分析、崩溃或第三方 SDK。

Host 的 `Info.plist`、entitlements、源代码和 UI test 必须作为负向证据接受扫描；任何新增权限 usage description、网络域名、Provider key、持久化、遥测或健康正文日志都构成新的隐私数据流，必须先更新本规范、DATA-01/API-01（如适用）、测试计划和相应同意/发布门禁。Simulator screenshot、XCTest attachment 和 accessibility hierarchy 只能使用合成或空白状态，不能变成健康数据外发渠道。

为定位内部 Host 失败，CI **仅在该 Host smoke 失败时**可以上传受限诊断包：失败 `.xcresult`、失败 XCTest 生成的当前屏幕截图和 accessibility hierarchy，以及由该结果包导出的失败附件。它们只允许来自固定合成 fixture，禁止真实账号、用户输入、位置、感觉、程度、草稿序列化、3D 命中或生产数据；不得打印到 Actions 日志，不得包含工作区、DerivedData 或通配临时目录。诊断包必须写入 CI runner 的专用 temporary directory、使用仅 `contents: read` 的仓库 Actions 权限、最短保留 3 天，并在失败之外不上传。它是失败定位证据，不是产品遥测、研究录屏、健康资料共享或设备/无障碍通过证据。

### 10.2 服务端

- 所有网络传输使用现代 TLS。
- 数据库、对象存储、备份和队列静态加密。
- 密钥由受控密钥管理系统管理，业务数据库不存明文主密钥。
- 身份数据与健康内容逻辑分离，使用随机内部 ID 关联。
- 生产、测试、分析和支持环境隔离。
- 不用真实生产健康数据填充开发或演示环境。
- 管理后台不提供无范围的全文搜索和批量导出。
- 备份恢复必须测试删除传播和访问控制。
- 数据导出使用短期、单用户、可撤回的下载凭证。

## 11. 访问控制

采用最小权限 RBAC 与必要的属性限制：

| 角色 | 默认权限 |
|---|---|
| 用户 | 查看、纠正、导出、删除自己的数据；管理授权 |
| 客服 | 默认看不到健康正文；仅处理账户和用户主动提交的最小片段 |
| 临床安全审核 | 只访问经批准、去标识化的事件或用户明确授权的事故材料 |
| 工程运维 | 访问系统指标和伪名审计，不访问健康正文 |
| 隐私/安全调查 | 经双人批准、限时访问必要数据 |
| 数据分析 | 只访问经批准的去标识/聚合数据，不访问原始文本 |
| 模型服务 | 只获得本次请求的最小上下文包 |

强制要求：

- 所有人工访问使用个人账户、强认证和限时权限；
- 高敏访问需要工单、目的、范围和双人批准；
- 禁止共享账号；
- 定期复核权限；
- 员工离职或角色变化立即撤权；
- 对读取、导出、修改、删除、分享和人工覆盖全部审计；
- 异常批量访问和跨用户访问触发告警。

## 12. 日志、追踪与审计

### 12.1 日志分层

| 层 | 允许内容 | 禁止内容 |
|---|---|---|
| 产品分析 | 页面 ID、耗时、错误码、无健康语义事件 | 原始文本、身体部位、程度、规则答案 |
| 崩溃/性能 | 调用栈、设备类别、性能指标、伪名请求 ID | Agent 上下文、报告正文、文件内容 |
| 安全审计 | 同意、数据源、规则 ID、Tier、版本、内容 ID、输出哈希 | 非必要的完整健康正文 |
| 受限事故材料 | 经批准的最小原始片段 | 与事故无关的历史档案 |

不得依赖“匿名”标签掩盖可重新识别的健康数据。任何进入第三方 SDK 的字段都必须通过网络流量验证。

### 12.2 最小审计事件

每次 Agent/安全流程至少记录：

- `audit_event_id`、`request_id`、时间和区域；
- 用户伪名 ID、会话和客户端版本；
- `consent_receipt_ids`；
- 实际访问的数据源和字段类别；
- 工具调用、目的和授权结果；
- `safetyBaselineId`；
- 红旗规则输入字段哈希、命中规则 ID 和最终 Tier；
- 输出模式；
- 使用的 `content_id` 与版本；
- 模型、Prompt 和策略验证器版本；
- 策略验证结果、失败原因与 `DegradedMode`；
- 用户确认、修改、拒答、撤回或分享动作；
- 最终输出摘要哈希；
- 人工访问、覆盖、停用或回滚记录。

审计系统必须能够回答：“这个用户在这个时间为什么看到了这条行动，系统用了哪些用户确认事实、规则、内容、模型和同意？”

### 12.3 防篡改与最小化

- 审计记录追加式保存并具备完整性校验。
- 安全审计与业务数据库分离。
- 审计正文最小化，优先保存 ID、枚举和哈希。
- 对确需保留的原始事故材料单独加密、授权和到期删除。
- 用户删除健康内容后，审计可以在法律和安全必要范围内保留无法回溯正文的最小证明，不得借审计名义永久保存完整健康数据。

## 13. 保留、删除与备份

### 13.1 保留计划

公开发布前必须批准正式 `RetentionSchedule`。每类数据必须有具体时长或明确事件触发，不能使用“长期”“必要时”等模糊表述。

| 保留类 | 触发点 | 规范要求 |
|---|---|---|
| 账户 | 账户有效期 | 账户删除后按正式计划删除或隔离必要记录 |
| 确认身体事件 | 用户选择保留 | 支持逐事件、Episode 和全账户删除 |
| 未确认草稿 | 创建时间 | 必须有短期自动过期 |
| 原始语音/图片 | 提取或确认完成 | 最短必要期限；具体值未批准不得上线云处理 |
| 上传原文件 | 用户选择与处理完成 | 与提取字段分开控制 |
| 分享链接 | 创建时间/用户撤回 | 必须有过期和撤回 |
| 普通日志 | 产生时间 | 不得含健康正文；按运维必要最短保留 |
| 安全审计 | 产生时间 | 按风险和法律必要保留；正文最小化 |
| 备份 | 备份创建 | 公开最大残留周期；到期不可恢复 |

`RetentionSchedule` 必须记录所有活动库、对象存储、搜索/向量索引、缓存、队列、分析仓库、日志、备份和供应商副本。

未确认内容到期不是单纯把 UI 标成 expired。到期事务必须：删除服务端 draft/raw text/临时来源和可识别的 Turn 正文；清空 Session.latest_turn_id 与个体 `retained_safety_action`；把 pending 或 approved-but-not-executing ApprovalIntent 置为 expired/invalidated；将可保留审批投影改为 `redacted=true` 的最小墓碑，删除 `display_summary`，Recovery 固定 `decision_result=null`；删除本地同步队列中的正文并留下不含健康内容的清理回执；旧 intent/turn/idempotency key 之后均为零副作用。幂等元数据/请求哈希可按安全周期保留，但响应正文的 TTL 不得超过来源；清理后同 key 只返回墓碑/410，禁止重放旧正文。`ApprovalIntent.expires_at` 不得晚于来源 Session/草稿 TTL。`persisting/executing` 不被普通 TTL 中断，由 watchdog 和事务日志收敛到 executed/failed；completed 正式资源按确认事件策略保留，不套用草稿 TTL。

R0/R1 草稿到期后不能继续显示已经过期的个体化安全快照，但也不能让帮助入口消失：App 全局层始终提供不提交健康正文的公共紧急/专业帮助入口，并按当前已发布地区内容重新解析。安全审计只保留 tier、规则/内容版本、时间、是否展示和结果类别等最小字段，不保留用户自由文本、位置细节或完整问题答案。

所有 ApprovalIntent approve（v1 为保存正式 Event、分享报告）在执行时都要求近期认证令牌，令牌绑定用户、动作类型、approval_id/intent digest、短有效窗且一次消费；Intent 创建时的旧认证不能替代执行时复验。deny 不要求近期认证。认证令牌禁止进入日志、分析或 Agent 上下文。提醒是用户明确设置命令，需通知同意与幂等控制，但不冒充 ApprovalIntent。

### 13.2 删除

删除流程必须覆盖：

1. 活动数据库；
2. 对象存储与缩略图；
3. 搜索和向量索引；
4. 缓存与队列；
5. 报告与分享链接；
6. 模型或 OCR 供应商可控副本；
7. 分析/导出数据；
8. 备份生命周期；
9. 本地设备缓存；
10. 长期记忆与派生特征。

删除任务必须可追踪、可重试、可验证。若某项数据依法不能立即删除，必须停止除存储和安全保护外的处理，并向用户说明类别、原因和期限。

用户主动分享给外部接收者的独立副本可能不再受产品控制；分享前必须说明。产品内分享链接必须支持撤回。

## 14. 用户权利与隐私中心

App 内隐私中心必须支持：

- 查看当前同意和系统权限；
- 查看本次 Agent 分析实际使用的数据来源；
- 查看长期档案字段的来源、时间和确认状态；
- 逐项纠正或标记过期；
- 撤回历史、HealthKit、上传文件、第三方 AI、通知和训练授权；
- 导出结构化事件、报告和同意记录；
- 删除单个事件、Episode、资料来源、Agent 长期记忆或账户；
- 查看报告分享对象、范围、有效期和撤回状态；
- 提交隐私请求、投诉和申诉；
- 查看隐私负责人或联系渠道。

账户创建后必须在 App 内提供删除账户入口，不得要求用户只能发邮件。

## 15. 安全事件与响应

### 15.1 事件类别

- 未授权读取或跨账号访问；
- 健康正文进入普通日志、分析 SDK、通知或崩溃平台；
- 未获同意向第三方模型或境外提供数据；
- 供应商将数据用于训练；
- 删除不完整或数据在索引/备份中异常恢复；
- 规则或 Agent 因权限错误发生安全降级；
- 输出或分享泄露他人数据；
- 账户接管、凭证泄露或批量导出；
- 审计记录缺失或被篡改；
- 模型/文档提示注入导致越权工具调用。

### 15.2 响应要求

必须具备：

- 24 小时责任人与升级链；
- 独立停用第三方模型、上传、分享、HealthKit 和普通 Agent 的开关；
- 撤销会话、密钥和下载链接；
- 保全最小必要证据；
- 影响范围与数据类别判断；
- 供应商联动；
- 法律要求下的主管部门和用户通知；
- 修复、删除、回滚和复测；
- 根因分析、责任人和完成期限；
- 是否需要生成新 SafetyBaseline 和重新取得同意的判断。

不得为调查方便无限期保留与事故无关的健康数据。

## 16. PrivacyBaseline 与 SafetyBaseline

隐私不是与安全发布分离的文档。DOC-00 定义的 `SafetyBaseline.consentNoticeVersion` 必须指向不可变的 Privacy Release Manifest。该 Manifest 至少绑定：

- 隐私政策版本；
- 数据字段登记版本；
- 数据流图版本；
- RetentionSchedule 版本；
- 供应商清单版本；
- 区域路由/跨境配置版本；
- Agent 工具权限策略版本；
- 审计事件 Schema 版本；
- 删除实现与验证报告版本；
- App Store Privacy 声明版本。

上述任一项发生语义变化时，必须生成新的 Privacy Release Manifest、提升 `consentNoticeVersion` 并创建新 SafetyBaseline。不能在不更新基线的情况下热切换模型地区、供应商保留策略或数据用途。

---

## 17. 发布门禁

以下任一项未满足，禁止公开发布：

- 未完成个人信息保护影响评估；
- 敏感信息、自动化决策、第三方提供或跨境场景没有完成适用的同意和法律机制；
- App 不能在用户拒绝可选权限后提供合理的手动/降级路径；
- Agent 能读取未授权或超出当前任务范围的数据；
- 第三方模型训练关闭缺少合同或技术证据；
- HealthKit 权限、隐私政策、App Store Privacy 与真实流量不一致；
- 原始健康正文进入普通日志、分析、崩溃或通知；
- RetentionSchedule 没有具体、已批准的保留期限；
- 删除未覆盖索引、缓存、对象存储、分享、供应商和备份；
- 账户删除不能在 App 内发起；
- 跨境处理无法证明必要性、机制、单独同意和区域路由；
- 模型备案/登记、公示和 AI 内容标识的适用性未完成判断；
- 无法通过 `safetyBaselineId` 重建同意、权限和数据流版本；
- 无停用、回滚、事故响应和泄露通知演练；
- `docs/11_TEST_AND_EVALUATION.md` 中隐私与安全硬门槛未通过。

权限绕过、跨账号访问、未经同意向第三方发送健康数据、删除失效和健康数据进入广告/分析链路不得通过“风险接受”豁免。
